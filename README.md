# 法律服务平台

这是结合《法律服务平台需求文档》调整后的法律服务平台。前端使用原生 HTML、CSS、ES modules，生产入口通过同源 Node 静态服务器代理 Python API；业务记录、鉴权、模型咨询和订单状态均以服务端数据为准。

## 启动

```bash
npm start
```

浏览器打开 <http://127.0.0.1:4173/>。预发布服务器入口为 `http://172.22.3.76:189/`。如果 4173 端口已被占用，可以使用：

```bash
PORT=4174 npm start
```

本地服务器预览时，可以监听所有 IPv4 网卡：

```bash
HOST=0.0.0.0 PORT=4173 npm start
```

通过 `http://服务器地址:4173/` 访问。未设置 `HOST` 时仍默认仅监听本机；正式环境应使用 HTTPS 域名和反向代理，不应直接暴露开发端口。

检查语法：

```bash
npm run check
```

运行业务状态测试：

```bash
npm test
```

## 保留的页面和流程

- 当事人工作台：法律问答、法律模型咨询、需求发布、找律师、报价比较、订单、文书中心和账户安全。
- 法律问答：民事、刑事、不确定三入口，事实/地区/时间/诉求采集，刑事身份和强制措施字段，风险提示和人工律师入口。
- 法律模型咨询：支持自由提问、领域选择、连续追问、材料元数据记录、咨询历史、反馈、复制和导出；咨询中的用户提问可整理成摘要，经授权后转为服务需求。预发布已接入受控的 OpenAI 兼容真实模型；附件目前只保存元数据，不会未经明确能力接入就声称已完成正文解析。
- 服务需求：问答摘要授权转需求，预算、地区、截止时间、交付物和公开范围；需求详情与报价列表。
- 律师连接：认证律师列表、领域/地区筛选、律师资质信息和报价流程。
- 订单履约：接受报价创建订单与服务合同，单次支付成功/失败重试，服务中、待交付、待确认、已完成、退款中、争议中等状态。
- 文书协作：服务合同、法律文书和交付物，版本、恢复为新版本、批注、访问授权、顺序会签、退回、撤回、催办和平台内确认。
- 售后与存证：退款/争议申请、运营处理、订单过程记录、版本指纹和必要元数据导出。
- 律师视角：线索、报价、订单、文书工作区、交付、资质与收款结算。
- 运营视角：律师审核、订单监管、售后争议、审计日志、服务类目和风险提示配置。

## 已移除或暂缓的原入口

- 已移除促销浮窗、AlphaClaw、峰会活动、小阿来信、试用剩余天数、旧版切换、原站备案和微信登录展示。
- 已合并合同审查、模板审查、补充协议审查、制度审查为订单内的文书审阅与版本协作。
- 独立类案检索、自动 AI 审查、并行会签、电子签署、分阶段付款、发票、托管结算、多组织合同管理暂缓，避免出现没有真实服务支撑的孤立入口。

主要业务页面使用以下 hash 路由：

```text
#/home
#/chat
#/model-chat
#/model-chat/咨询ID
#/requests
#/lawyers
#/orders
#/order/订单ID
#/docs
#/doc/文书ID
```

法律模型咨询通过 `model-consultation.js` 和 `model-consultation.css` 独立维护。咨询保存于原有业务存储中的 `modelChats` 字段；旧数据缺少该字段时补为空数组，保留需求、订单与文书。原始结构化问答继续使用 `sessions`。咨询转需求会创建标注来源与生成时间的摘要快照，只包含用户提问与材料元数据。

## 数据和边界

前端不连接第三方现有平台账号、案例库或合同审查服务。需求、报价、订单、文书版本、会签、通知、售后和审计数据保存于后端数据库；浏览器只在内存保存当前会话，不把业务事实写入 `localStorage`。注册使用服务端一次性算术问答，不依赖邮箱验证码；预发布支付入口保持关闭，未取得真实商户签约配置前不会伪造支付成功；文件按服务端 ACL 下载，附件正文解析能力仍需独立接入和验收。

保留服务清单、页面映射和删除/暂缓决策见 [服务清单与页面调整方案](./服务清单与页面调整方案.md)。如需投入生产，可替换为自己的品牌与素材，并接入鉴权、AI/检索、文件存储、支付、电子签署、存证和运营后台 API。

## Python 后端

后端实现位于 [`backend/`](./backend/)，包含账户鉴权、法律咨询、需求/报价、订单/支付、文书会签、文件、通知、售后和审计 API。启动与测试说明见 [`backend/README.md`](./backend/README.md)，架构映射见 [`backend/ARCHITECTURE.md`](./backend/ARCHITECTURE.md)。

前后端联通、支付验签、模型密钥授权、依赖就绪检查及律师入驻的实施与验收方案，见 [部署问题修复与生产完善方案](./部署问题修复与生产完善方案.md)。
